# ContextDock v0.2.0 — Cross-platform OpenCode workflow

ContextDock keeps persistent project context across AI coding sessions. v0.2.0 brings cross-platform launcher improvements, prompt history, and a more polished overall experience.

## Highlights

- **Cross-platform OpenCode launcher** — macOS, Linux, and Windows all get robust, script-based launching that correctly passes prompt content via `--prompt`.
- **Prompt History** — Every generated launch prompt is saved as a timestamped snapshot under `.context-bridge/history/`, viewable and copyable from the UI.
- **Editable Requested Task** — Customize the task description before generating a launch prompt.
- **Expanded test coverage** — 62 passing Rust tests, including cross-platform launcher helpers and security checks.

## Platform support

### macOS
- Launches OpenCode in Terminal.app.
- Prompt content passed safely via `opencode --prompt "$(cat <prompt-path>)"`.

### Linux
- Writes a helper script at `.context-bridge/launch-opencode.sh`.
- Launches via the first available terminal emulator from: gnome-terminal, konsole, xfce4-terminal, mate-terminal, alacritty, kitty, xterm.
- Terminal stays open after OpenCode exits.

### Windows
- Writes a helper script at `.context-bridge/launch-opencode.ps1`.
- Launches via Windows Terminal (`wt.exe`) if available, falls back to PowerShell.
- Uses `Get-Content -Raw` for safe multi-line prompt handling.
- Terminal stays open after OpenCode exits.

## Known limitations

- Windows launcher still needs manual validation on a real Windows machine.
- Linux launcher should be manually tested across different terminal emulators.
- Full session capture using `sessions.json` is not implemented yet.

## Upgrade notes

- Existing `.context-bridge` folders remain compatible.
- New prompt history files are saved under `.context-bridge/history/`.
- The new launcher scripts (`launch-opencode.sh` / `launch-opencode.ps1`) are generated on each launch — no manual migration needed.
